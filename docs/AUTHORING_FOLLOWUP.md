# 質問ドリル（フォローアップ）作問ガイド

対象: `data/questions_followup_v1.json`（マスター）→ `app/data/` へコピーして同梱。
型の定義と線引きの根拠は [followup/FOLLOWUP_PATTERNS.md](followup/FOLLOWUP_PATTERNS.md) を正とする。

## 形式

```json
{
  "id": "fu001",
  "kind": "followup",
  "category": "詳細",
  "difficulty": 1,
  "utterance": "最近、仕事がバタバタしてて",
  "phrase": "バタバタって、具体的にはどんな感じなんですか？",
  "answer": "1",
  "ok": ["3"],
  "explanation": "…"
}
```

- `kind` は必ず `"followup"`（アプリはこのキーで採点・画面を分岐する）
- `answer` / `ok` のキー（7分類）: `1` 詳細（具体・背景） / `2` 感想・意見 / `3` 理由・目的 / `4` 結果・影響 / `5` 対策・次の一手 / `6` 比較・対比 / `7` 振り返り
- `category` は answer に対応する型名: 詳細 / 意見 / 理由 / 結果 / 次の一手 / 比較 / 振り返り。成績画面の型別集計に使う
- `utterance`（相手の発言）は任意。文脈がないと型が決まらない問題には必須
- `ok` は「惜しい」と判定する許容キー。境界例（詳細(背景)↔理由、振り返り↔詳細(背景) など）にのみ付け、乱用しない
- `explanation` には「なぜその型か」を書く。境界例は線引きを必ず書く

## 品質基準

1. **一意性**: `ok` なしの問題は、型が一つに決まる言い回しにする。迷ったら `utterance` で文脈を固定する
2. **自然さ**: 実際の雑談で口にできる文にする（尋問調・書き言葉は不可）
3. **境界の学習価値**: 詳細(背景)＝経緯・事実と理由＝動機・価値、結果＝起きたことと次の一手＝これから、の対比が学べる問題を難易度2〜3に配置する
4. **難易度**: 1=フレーズだけで即答可、2=文脈が必要、3=境界例
5. **配分**: 詳細は具体化・背景の2系統があるため2倍(10問)、他は各5問（v1 は計40問）。増補時もこの比率を保つ

2. `app/data/questions_followup_v1.json` へコピー
