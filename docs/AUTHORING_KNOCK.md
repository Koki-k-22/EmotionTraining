# 100本ノック（フォローアップクエスチョン生成）作問ガイド

対象: `data/questions_knock_v1.json`（マスター）→ `app/data/` へコピーして同梱。
型の定義と線引きは [followup/FOLLOWUP_PATTERNS.md](followup/FOLLOWUP_PATTERNS.md) を正とする。

## 練習の狙い

質問ドリル（`questions_followup_v1.json`）が「質問文 → 型を当てる」分類練習なのに対し、
ノックは「相手の回答文 + 指定の型 → 自分で質問を作る」生成練習。
**フラッシュカード形式**: 質問は入力せず頭の中（できれば声に出して）で作り、「答えを見る」で模範解答を開いて
「次へ」で進む。採点・自己評価はなし（テンポよく100本回すことを優先。2026-08-30 に◎○×自己採点を廃止）。
このため記録・復習キュー・型別成績の対象外（連続日数のみ更新）。
**模範解答は1つの型につき3例**: 同じ型でも狙いどころ（どこを掘るか）を変えた3例を用意する
（例: 具体化なら「曖昧語の中身」「頻度」「過ごし方」）。どれかと同じ狙いが出ていれば良し、別の切り口でも型が合っていれば良し。

## 回答文の設計原則 —「材料を入れる」ではなく「余地を残す」（2026-08-31 改訂）

初版は回答文3〜4行（100〜170字）に「8型すべての質問が成立する材料」を詰め込む方針だったが、
**きっかけ・頻度・感想・その後まで回答文が先に語ってしまい、質問の余地がなくなる**という
ユーザー指摘（2026-08-31）で方針転換した。回答文は**会話の一投目**とする。

1. **1〜2文、40〜80字目安（上限90字。テストが25〜90字を検証）**の話し言葉
2. 言うのは**話題への答えの核 ＋ フック1〜2個**だけ。
   フック = 拾って掘れる取っ掛かり: 曖昧語（「ととのう」）、固有の物・場所（「近所の銭湯」）、
   軽い感情語（「意外と楽しくて」）、謙遜・ぼかし（「地道にやっただけなんですけど」）
3. **8型で聞ける内容を先に言わない**: きっかけ・経緯（→1b）、頻度・数字・詳しい様子（→1a）、
   感想・評価の中身（→2。「ハマってる」「びっくりした」程度の話題上当然の感情語は可）、
   理由・こだわり（→3）、その後・周りの反応（→4）、これから（→5）、他との比較（→6）、
   学び・総括（→7）。数字は、それ自体が話の核（自慢の中身など）の場合のみ最小限可
4. ペルソナの声（年齢・職業・生活環境）は言い回しでにじませる（内容で語りすぎない）

## 8つの型

PATTERNS.md の7分類のうち、①詳細を「具体化」「背景」に分けて8型とする。キーは以下。

| キー | 型 | アンカー |
|---|---|---|
| `1a` | 詳細（具体化） | 具体的には、どういうことですか？ |
| `1b` | 詳細（背景） | きっかけは何だったんですか？ |
| `2` | 感想・意見 | 〜については、どう思ってますか？ |
| `3` | 理由・目的 | それを選んだ決め手は何だったんですか？ |
| `4` | 結果・影響 | それで、どうなったんですか？ |
| `5` | 対策・次の一手 | 次は、どうするんですか？ |
| `6` | 比較・対比 | 他のと比べて、どうなんですか？ |
| `7` | 振り返り | 今振り返ってみて、どうですか？ |

## 形式

```json
{
  "version": 3,
  "topics": { "a": "最近ハマっていること", "b": "…", "c": "…", "d": "…", "e": "…" },
  "personas": { "p01": { "name": "田中 美咲", "profile": "28歳・Webデザイナー・都内で一人暮らし" }, "…": {} },
  "items": [
    {
      "id": "kn_a01",
      "topic": "a",
      "persona": "p01",
      "answer": "最近はサウナにハマってますね。近所の銭湯なんですけど、「ととのう」ってやつが最近ちょっと分かってきた気がして。",
      "questions": {
        "1a": [
          { "phrase": "「ととのう」って、具体的にはどういう感覚なんですか？", "why": "曖昧語の中身" },
          { "phrase": "どのくらいのペースで行ってるんですか？", "why": "頻度" },
          { "phrase": "サウナの間って、何して過ごしてるんですか？", "why": "過ごし方" }
        ],
        "1b": [], "2": [], "3": [], "4": [], "5": [], "6": [], "7": []
      }
    }
  ]
}
```

- `id` は `kn_{話題}{ペルソナ番号}`（例: 話題 a × p07 → `kn_a07`）
- 話題は5つ固定: (a) 最近ハマっていること (b) 最近びっくりしたこと (c) 子どもの頃ハマっていたこと
  (d) 今までで一番自慢したいこと (e) 今までで一番失敗したこと
- ペルソナ10人は全話題に回答する（10×5=50本）。年齢・職業・生活環境を散らす
- `answer` は上の「回答文の設計原則」に従う。短くても8型の質問はすべて成立する
  （むしろ言っていないことが多いほど、どの型もまっすぐ聞ける）
- `questions` は8型すべて必須で、**各型に3例の配列**。`phrase` は実際に口にできる一文、`why` は狙いどころの短いラベル。同一回答文内で `phrase` の重複禁止（テストが検証）
- アプリ側は `app/js/knock.js` の `expandKnock` で (回答文×型) の仮想問題（id `kn_a01_1a` 等、`kind: "knock"`）に展開する

## 模範質問の品質基準

1. **前提にしてよいのは回答文に書かれたことだけ**: 回答文に根拠のない情報（頻度・同行者・道具など）を
   前提にした質問を作らない
2. **既出のことを聞かない**（ユーザー指摘 2026-08-29）: 回答文に既に書かれている情報を尋ねる質問は不可。
   回答文の言葉は拾ってよいが、聞くのは**その先**（中身・経緯・周りの反応・次など、まだ語られていないこと）。
   回答文を「一投目」に絞った現行方針では、頻度・きっかけ・感想の中身などはむしろ積極的に聞きに行く
3. **型の一意性**: 模範質問は指定の型に読めること。特に 背景(1b)↔理由(3)、結果(4)↔次の一手(5)、
   意見(2)↔振り返り(7) の境界を PATTERNS.md の線引きどおりに守る
   - 背景: 過去の経緯・事実（いつ・どうやって・きっかけ）／ 理由: 今の動機・価値（なぜ・決め手・何のため）
   - 結果: すでに起きたことの続き ／ 次の一手: まだ起きていないこと
   - 意見: 対象への評価 ／ 振り返り: 自分の過去の再解釈
   - 話題(e)失敗では、理由(3)は「当時の判断・動機」を聞く形が作りやすい
4. **自然さ**: 相手の言葉（「ととのう」など）を拾う。尋問調・書き言葉は不可
5. **3例は狙いどころを変える**: 同じ型の3例は、回答文の別々のフックや切り口を掘る。模範はあくまで例で、一致する必要はない

## 出題の仕組み

- 1セッション = 100問（既定）。50回答文を1周ずつ回し、各周で回答文ごとにランダムな型を1つ選ぶ
  → 各回答文が2型ずつ、同じ回答文は連続しにくい。未回答の (回答文, 型) を優先
- 「10本だけ」は同じ仕組みで10問
